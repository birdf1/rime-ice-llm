修正 CapsLock 结论：改 good_old_caps_lock 无效，大写只能靠 Shift

上一版以为 good_old_caps_lock: false 能让 CapsLock 变成纯大小写键，
实测（Weasel 0.17.4 + librime 1.13.1）证明不行：

  CapsLock 开 + good_old_caps_lock: false -> 打 abc 得 abc（小写）
  CapsLock 开 + good_old_caps_lock: true  -> 打 abc 得 abc（小写）

两种设置下 CapsLock 都会进英文模式，且模式内字母固定小写。
原因是 CapsLock 被输入法当「中英文开关」吃掉，键事件没到 Windows，
系统 caps 状态不翻转，所以永远小写。这是 rime 的设计，配置改不动。

大写走 Shift，实测正常：
  左 Shift        -> 切英文
  Shift+a,Shift+b -> A、B（整串测试输出 ABc）

还发现一个更隐蔽的问题：CapsLock 开→关 之后会留下「有编码、没候选」的
半死状态，候选栏看着在、数字键却选不中，字母也上不了屏，需要重启
WeaselServer 或再切一次模式才恢复。这是「数字键选不中」的成因之一。

改动：
- default.custom.yaml：good_old_caps_lock 改回 true（改 false 没用，只会多一层困惑），
  并显式写明 switch_key/Caps_Lock: clear，保证切换时清空未上屏编码
- README 第 16 条重写，补上实测数据和半死状态的描述
- tools/test_ime_vk.ps1：
    * 字母和数字都改为携带真实扫描码。只给 wVk 时 ToUnicode 拿不到物理
      键位，大小写状态不会被应用，测出来永远是原始字符，会误判成「没有大写」
    * 新增 S-x 语法表示 Shift+x，用于验证大写通道

顺带记下：rime 会按选过的候选调整词频，测试反复提交同一输入时候选顺序会变，
「ya+2 上次出亚这次出压」不是 bug。
